## 🧭 三条阅读路线

### 路线 A：新组员第一次上手（约 40 分钟）

```
README.md（根目录，项目门面）
  → docs/快速上手.md（把项目跑起来）
  → docs/团队协作指南.md（知道怎么协作）
  → docs/组员任务清单.md（领自己的任务）
```

### 路线 B：要改代码 / 加功能（按需查）

```
docs/数据库与API契约.md（改接口前后各读一遍）
  → docs/代码说明.md（定位到具体文件与流程）
  → docs/项目逻辑流程.md 第三节（扩展点：加功能该动哪些文件）
```

### 路线 C：答辩准备

```
docs/答辩预案.md（台词 + 流程 + 问答）
  → docs/数据说明.md（数据真实性问答弹药）
  → docs/项目逻辑流程.md 第二节（被要求画架构/时序图时）
```

## ✏️ 文档维护规则

1. **改接口/数据库/配置 → 同一次 PR 内更新** `数据库与API契约.md`（+ `apifox-import.json`）
2. **改架构/新增文件 → 更新** `代码说明.md` 与根 `README.md` 的目录结构
3. **任务进度变化 → 更新** `组员任务清单.md`（打勾即可，别删历史）
4. **文档与代码不一致时**：以代码为准，顺手修文档，别留着坑下一个人
