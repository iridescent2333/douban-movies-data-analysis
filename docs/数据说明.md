## 一、数据来源：Kaggle 公开豆瓣数据集（真实数据，可溯源）

**⚠️ 本项目不使用任何模拟/编造数据。** 全部 2050 条记录都是豆瓣真实存在的电影，
评分、评价人数、简介、海报 URL 均与豆瓣一致，主键直接使用豆瓣条目 subject id（可溯源）。

| 项目 | 说明 |
|------|------|
| 数据集 | [Douban Movies Dataset](https://www.kaggle.com/datasets/dengfuping/douban-movies-dataset) |
| 许可证 | **CC0: Public Domain**（公有领域，可自由使用） |
| 镜像仓库 | [github.com/dengfuping/douban-movies-spider](https://github.com/dengfuping/douban-movies-spider)（`data/douban_all_movies.csv`） |
| 采集方式 | 数据集作者 2025 年通过豆瓣公开页面采集（本项目**不写爬虫、不访问豆瓣网站**，规避 robots 协议风险） |
| 规模 | 原始 2065 条 → 清洗后 **2050 条**有效记录 |
| 覆盖 | 1931–2026 年上映、28 种类型、全球主要制片地区；评价人数中位数约 17.5 万 |

原始字段：movie_id / title / rating / total_ratings / directors / actors / screenwriters /
release_date / genres / countries / languages / runtime / summary / link / **poster** / tags。

### 清洗转换规则（scripts/build_dataset.py）

| 规则 | 说明 |
|------|------|
| 主键 | 从豆瓣链接提取 subject id（如 `https://movie.douban.com/subject/1292052/` → `1292052`） |
| 去重 | 按豆瓣链接去重 |
| 过滤 | 无标题/评分/评价人数/类型或日期非法的记录剔除（共剔除 15 条） |
| 国家 | 原始为 " / " 分隔（合拍片），取第一个作为主制片地区 |
| 类型 | "剧情, 犯罪" 拆分后入库 genres / movie_genres 两张表（一部电影多类型） |
| 片长 | "142分钟" 提取数字 |
| 档期 | 按上映月份映射：春季档(3-5) / 暑期档(6-8) / 秋季档(9-11) / 贺岁档(12-2) |
| 禁止编造 | 公开数据集**没有真实预算/票房**，因此全项目不做"成本-票房"统计（散点图改为"评分×热度"） |

## 二、数据导入 MySQL 步骤

### 方式 A（推荐，全自动）：启动后端自动导入

数据文件已随仓库分发：`backend/src/main/resources/data/movies.csv`（真实数据，2050 条）。

1. 确认 MySQL 里已建库（可用 `docs/mysql-init.sql`）：
   ```sql
   CREATE DATABASE IF NOT EXISTS movie_dashboard DEFAULT CHARACTER SET utf8mb4;
   ```
2. 配置好 `application-local.yml` 的数据库账号密码；
3. 启动后端 —— Hibernate 自动建表，`DataInitializer` 检测到 movies 表为空时
   自动把 2050 条真实数据写入 MySQL（控制台会打印"真实数据加载完成！"）。

### 方式 B（手动）：SQL 脚本导入

1. 执行建表脚本 `backend/src/main/resources/schema.sql`（含建库）；
2. 用 `LOAD DATA` 导入 CSV（Windows 下注意路径正斜杠 + `CHARACTER SET utf8mb4`）：
   ```sql
   LOAD DATA LOCAL INFILE 'D:/.../backend/src/main/resources/data/movies.csv'
   INTO TABLE movies
   FIELDS TERMINATED BY ',' OPTIONALLY ENCLOSED BY '"'
   LINES TERMINATED BY '\n'
   IGNORE 1 LINES
   (id, title, director, lead_actor, country, release_year, duration,
    rating, vote_count, release_date, season_tag, intro, poster_url, link, @genres);
   ```
   > 类型多值列需要再写一段存储过程拆分进 `genres` / `movie_genres`，
   > **推荐直接用方式 A**，由后端统一完成拆分，保证关联表一致。

### 重置数据（重新导入）

```sql
-- 在 movie_dashboard 库执行；然后重启后端即自动重新导入
SET FOREIGN_KEY_CHECKS = 0;
DROP TABLE IF EXISTS movie_genres;
DROP TABLE IF EXISTS genres;
DROP TABLE IF EXISTS movies;
SET FOREIGN_KEY_CHECKS = 1;
```

### 换/更新数据集

1. 下载新版 `douban_all_movies.csv` 放到 `data-source/`；
2. 运行 `python3 scripts/build_dataset.py --input data-source/douban_all_movies.csv --output backend/src/main/resources/data/movies.csv`；
3. 执行上面的重置 SQL 并重启后端。

## 四、海报图片为什么走后端代理？

豆瓣海报 CDN（`img*.doubanio.com`）有**Referer 防盗链**：实测只有携带
`Referer: https://movie.douban.com/` 的请求返回 200，无 Referer / 其它站点 Referer
一律返回 418。浏览器安全策略禁止页面伪造 Referer，所以前端 `<img>` 直连必然失败。

解决：后端提供 `GET /api/works/{id}/poster?size=small|large` 代理——
服务端携带豆瓣 Referer 拉取图片字节流，**MD5 为 key 落盘缓存**（海报不变，永久有效），
前端同源引用。首次约 0.5s，缓存命中 0.01s；仅白名单 `img*.doubanio.com`，防 SSRF。
