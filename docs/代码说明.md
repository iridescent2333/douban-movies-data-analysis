## 一、整体架构

系统采用前后端分离 + Nginx 反向代理的三层结构：

```
┌──────────────────────────────────────────────────────────────┐
│  浏览器 (Chrome)                                              │
│  index.html + style.css + 13 个 JS 模块 + ECharts CDN          │
└───────────────────────┬──────────────────────────────────────┘
                        │ 同源请求 http://localhost:8083/ 与 /api/**
                        ▼
┌──────────────────────────────────────────────────────────────┐
│  Nginx :8083                                                  │
│  ├─ 静态资源：root → frontend/dist（JS/CSS 7 天缓存）           │
│  └─ location ^~ /api/ → proxy_pass http://127.0.0.1:8081/api/ │
└───────────────────────┬──────────────────────────────────────┘
                        ▼
┌──────────────────────────────────────────────────────────────┐
│  Spring Boot :8081                                            │
│  Controller 层  →  Service 层  →  Repository 层               │
│  （参数绑定）      （业务聚合）     （JPA 数据访问）             │
└───────────────────────┬──────────────────────────────────────┘
                        │ Hibernate / JPA
                        ▼
┌──────────────────────────────────────────────────────────────┐
│  MySQL 8.0 :3306   movie_dashboard                            │
│  movies / genres / movie_genres / movie_financials            │
└──────────────────────────────────────────────────────────────┘
```

**为什么这样分层**

| 决策 | 理由 |
|------|------|
| 前端请求全部走 Nginx 同源代理 | 浏览器视角下前后端同域，**天然无跨域**；同时保留后端 `CorsConfig` 作为直连调试时的兜底 |
| Controller 不做业务逻辑 | 保证换数据源（如接 Redis 缓存）时不必改动接口层 |
| Service 负责聚合与二次过滤 | 多类型的 AND 语义、内存分组统计都在这一层统一处理 |
| Entity 与 DTO 分离 | 数据库字段变动不影响接口契约；前端只拿到它需要的字段 |

## 二、后端模块职责

包路径：`backend/src/main/java/com/movie/dashboard/`

| 文件 | 职责 | 改动时注意 |
|------|------|-----------|
| `MovieDashboardApplication.java` | 启动类。容器就绪后打印 API 基地址（端口从环境读取） | 不改业务逻辑 |
| **config/CorsConfig.java** | 统一跨域配置（`allowedOriginPatterns`），用于绕过 Nginx 直连后端的场景 | 生产环境应收敛为具体域名白名单 |
| **config/DataInitializer.java** | `CommandLineRunner`：启动时检测 `movies` 表是否为空，空则用 OpenCSV 读 `data/movies.csv` 分批（BATCH_SIZE=50）写入 MySQL | 已有数据时自动跳过；想重载需先 TRUNCATE 两张表 |
| **controller/MovieController.java** | `GET /api/movies`（分页+多条件筛选）、`GET /api/movies/{id}`（详情）、`GET /api/movies/filters`（下拉选项） | URL 路径改动需同步前端 `main.js`；`genres` 参数前端传**逗号分隔**（`genres=科幻,动作`），Spring 亦兼容重复参数（`?genres=科幻&genres=动作`） |
| **controller/StatsController.java** | 6 个 `/api/stats/*` 图表接口 + 1 个聚合接口 `/api/stats/overview`；每个都用私有方法 `buildQuery()` 把公共筛选参数组装成 `MovieQueryDTO` | `top-directors` 的 `n` 后端默认 **10**，前端实际传 `TOP_N=20`；新增图表接口时复制此模式即可 |
| **service/StatsService.java** | 6 类图表聚合 + 看板聚合。核心改造：把"取数"（`loadContext`）与"算数"（`computeXxx`）拆开——单接口取一次数据算一次，`overview()` **取一次数据算全部 6 类图表 + KPI** | 类型筛选统一为 **AND**（与列表接口一致）；统计仍是 Java 内存分组，数据量到万级应改为 SQL `GROUP BY` |
| **service/MovieService.java** | 分页查询、详情组装、筛选器选项聚合；多类型筛选为 **AND 语义**，且**先过滤后分页**（多类型时全量取出再手动分页） | 早期实现是"先分页再内存过滤"，导致"科幻+动作"这类组合因第一页恰好不满足而被滤成空列表（已修复） |
| **service/StatsService.java** | 6 类图表聚合（年份趋势/类型对比/成本票房散点/热力矩阵/档期分析/导演 TOP）；通用 `filterMovies()` 供所有统计复用 | 当前为**内存分组**实现，数据量到万级应改为 SQL `GROUP BY` |
| **repository/MovieRepository.java** | 多条件 JPQL + 分页查询、年份/国家 distinct 查询 | JPQL 里的实体字段名改动会同步影响这里 |
| `repository/GenreRepository.java` | 类型字典查询 | — |
| `repository/MovieFinancialRepository.java` | 财务数据查询 | — |
| **entity/Movie.java** | `movies` 表映射，与 `Genre` 多对多（`@JoinTable movie_genres`） | 年份字段列名是 `release_year`（避开 SQL 保留字 `YEAR`） |
| **entity/Genre.java** | `genres` 字典表 | — |
| **entity/MovieFinancial.java** | `movie_financials`，主键由 `@MapsId` 从 Movie 派生的一对一 | 保存时必须 `f.setMovie(managedMovie)`，且 Movie 必须先落库 |
| **dto/（10 个）** | 请求/响应对象。`MovieQueryDTO` 承载全部筛选参数；其余为各类图表的响应结构 | 新增字段前端即可直接读取 |
| **exception/Result.java** | 统一响应包装 `{code, message, data}`，`code=0` 表示成功 | 前端 `api.js` 同时兼容 `0` 与 `200` |
| **exception/GlobalExceptionHandler.java** | `@ControllerAdvice` 兜底：404 实体不存在、400 参数校验/类型不匹配、500 内部错误。**对外不暴露堆栈**，详细堆栈只写日志 | 新增异常类型在此加一个 `@ExceptionHandler` |

## 三、前端模块职责

路径：`frontend/dist/`

| 文件 | 职责 | 关键点 |
|------|------|--------|
| `index.html` | 单页骨架：Header / 筛选条 / KPI 区 / 图表网格 / Tab 面板 / 电影列表 / 详情弹窗 / 页脚 | 元素 ID 是 JS 的挂载锚点，改名要同步 JS |
| `css/style.css` | 明暗两套主题（CSS 变量 + `body.dark`）、CSS Grid 布局、空数据占位样式 | 主色变量 `--primary`，豆瓣绿 `#42AC4E` |
| `js/config.js` | 全局配置（`window.APP_CONFIG`）：API_BASE、防抖时长、缓存 TTL、分页大小、TOP N、超时 | **API_BASE 为空串**：走 Nginx 同源代理 |
| `js/theme.js` | **设计令牌中枢**：CSS 变量读取、分类色板、通用 option 片段；注册 ECharts 主题 `app-light` / `app-dark` | UI 调优只改这一个文件；8 个图表模块统一调用 `UI_THEME.current()` 取主题名 |
| `js/chart-config.js` | **图表声明表**（纯数据）：每个图表的容器 id、数据来源、转换函数、所属 Tab | 新增图表 = 写一个模块 + 加一行声明 |
| `js/echarts-loader.js` | ECharts 加载器：本地 `vendor/echarts.min.js` 优先，缺失时依次回退 4 个 CDN 镜像，全失败广播 `echarts:error` | 保证断网/被墙时页面给出明确提示，而不是永远停在"加载中..." |
| `js/charts/registry.js` | **图表注册中心**：统一 init/render/resize/dispose/主题切换/空态/错误态；Tab 内图表懒渲染；rAF 合帧 | `main.js` 不再直接操作 8 张图，调度集中在此 |
| `js/main.js` | 应用入口：初始化筛选器 → 绑定事件 → 拉取 `/api/stats/overview` → 交给注册中心渲染 → 列表/弹窗 | `reloadAll()` 是总调度入口；聚合接口不可用时自动降级为旧的 6 接口 |
| `js/utils/api.js` | Fetch 封装：拼 query string、8 秒超时（`AbortController`）、`code` 校验、localStorage 5 分钟缓存、**请求去重 + 取消陈旧请求** | 连续筛选时 abort 上一轮请求，避免旧数据覆盖新数据 |
| `js/utils/debounce.js` | 防抖与节流工具 | 筛选变化 300ms 后才触发请求 |
| `js/utils/ui.js` | Toast 提示、Loading 遮罩、Modal 弹窗、空数据标记 | `markEmpty(id)` / `clearEmpty(id)` 供图表模块调用 |
| `js/charts/*.js`（8 个） | 每张图表一个独立 IIFE 模块，挂载到 `window.Charts.<图表名> = { render, resize, dispose }`；内部处理 ECharts init/dispose/主题/空数据 | 主题名来自 `UI_THEME.current()`，配色统一由 theme.js 提供 |

所有 JS 均为 IIFE 模块，仅通过 `window.APP_CONFIG` / `window.API` / `window.Charts` / `window.UI_UTILS` 暴露接口，**不污染全局作用域**。

## 四、核心流程

### 4.1 启动与数据初始化

```
mvnw spring-boot:run
  → Spring 容器启动
  → Hibernate 读 application.yml，按 ddl-auto=update 建/更新 4 张表
  → DataInitializer.run() 执行
      ├─ movieRepository.count() > 0 ? 跳过加载 : 继续
      ├─ OpenCSV 读 classpath:data/movies.csv
      ├─ 保存 14 个 Genre（去重）
      ├─ 循环保存 Movie（每 50 条 flush 一次），务必接回返回值：m = movieRepository.save(m)
      └─ 若 budget / box_office / release_date 任一非空，关联保存 MovieFinancial（850 条，每部电影一条）
  → 打印 "API 基地址 : http://localhost:8081/api"
```

> ⚠️ **易踩的坑**：`movieRepository.save(m)` 必须接返回值。CSV 里 Movie 自带 ID，Spring Data 会走 `merge()`，返回的才是受管实体；不接回会导致后续保存 `MovieFinancial` 时报 `detached entity passed to persist`。

### 4.2 用户改筛选条件 → 图表刷新（联调主线）

```
用户拖动年份滑块 / 勾选类型
  ↓ collectFilterState() 收集 UI 状态
  ↓ debounce 300ms
  ↓ reloadAll()
      ├─ API.cancelInFlight() 取消上一轮未完成的请求（避免旧数据覆盖新数据）
      ├─ GET /api/stats/overview（1 次请求，带全部筛选参数）
      │     后端：1 次 movies 查询 + 1 次 financials 查询 → 内存里算出 6 类图表 + KPI
      ├─ renderKPIsFromOverview(data) 渲染 4 个 KPI
      ├─ ChartRegistry.renderAll(data)
      │     ├─ 非懒渲染图表：rAF 合帧后逐个 render
      │     └─ 懒渲染图表：仅当前激活的 Tab 绘制
      └─ loadMovieList() 刷新当前页（注意页码换算：page = 页面显示页码 - 1）
  ↓ ECharts 重绘（先 dispose 再 init，避免 resize 错乱）
```

> 降级路径：若后端未升级（没有 `/api/stats/overview`），前端会自动切回"6 个统计接口并发"的旧模式，功能不受影响，只是慢一些。

### 4.3 为何需要「数据转换层」

后端返回通用扁平 DTO 数组，而各 ECharts 图表期望的数据结构不同。转换层集中在 `main.js` 的 4 个 `transform*()` 函数：

| 图表 | 后端返回 | 前端期望 | 转换函数 |
|------|---------|---------|---------|
| 年代趋势 | `[{year, count, avgRating}]` | `{years:[], counts:[], avgRatings:[]}` | `transformYearTrend` |
| 成本票房散点 | `[{budgetWan, boxOfficeWan, rating, title}]` | `[{movie, cost, boxOffice, rating, genre}]` | `transformScatter` |
| 热力矩阵 | `[{country, genre, avgRating}]` | `{countries:[], genres:[], data:[[i,j,v]]}` | `transformHeatmap` |
| 档期分析 | `[{seasonTag, ...}]` | `[{season, ...}]` | `transformSeason` |
| 类型对比 / 导演 TOP | — | 字段直接匹配 | 无需转换 |

### 4.4 分页约定（易错点）

| 位置 | 基准 | 说明 |
|------|------|------|
| 后端 `MovieQueryDTO.page` | **0-based** | Spring Data `PageRequest.of(page, size)` 约定 |
| 前端 `pageState.page` | **1-based** | UI 显示"第 1 页"更符合直觉 |
| 换算位置 | `main.js: loadMovieList()` | 发送请求时传 `page: pageState.page - 1` |

响应结构遵循 Spring Data Page：`content`（数据数组）、`totalElements`（总数）、`totalPages`（总页数）。

## 五、数据模型

```
┌──────────┐        ┌──────────────┐        ┌──────────┐
│  genres  │        │ movie_genres │        │  movies  │
├──────────┤        ├──────────────┤        ├──────────┤
│ id   PK  │───1:N──│ genre_id FK  │──N:1───│ id   PK  │
│ name UQ  │        │ movie_id  FK │        │ title    │
└──────────┘        └──────────────┘        │ director │
                                            │ country  │
                                            │ release_year  ← 列名不是 year（YEAR 是 SQL 保留字）
                                            │ rating   │
                                            │ vote_count│
                                            └────┬─────┘
                                                 │ 1:1（@MapsId）
                                            ┌────▼────────────┐
                                            │ movie_financials│
                                            ├─────────────────┤
                                            │ movie_id  PK/FK │
                                            │ budget_wan      │
                                            │ box_office_wan  │
                                            │ release_date    │
                                            │ season_tag      │
                                            └─────────────────┘
```

**设计规范说明（答辩常问）**

| 设计点 | 依据 |
|--------|------|
| 类型拆为字典表 + 关联表 | 第三范式：类型是多值属性，逗号拼接违反原子性 |
| 财务数据独立成表 | 字段稀疏（仅约半数电影有预算+票房数值），独立建表避免大量 NULL 列 |
| `release_year` / `rating` / `country` 建索引 | 这三个字段是高频筛选条件 |
| 主键用 BIGINT | 便于后续数据量扩展 |

`movie_financials` 现有 **850 行**（每部电影一条，只要 budget / box_office / release_date 任一非空即建行），其中 **418 条**同时含预算+票房数值——散点图、档期图、成本效益图实际可用的是这 418 条。

DDL 脚本见 `backend/src/main/resources/schema.sql`（同时由 Hibernate `ddl-auto: update` 自动生成）。

## 六、配置说明

`application.yml` **不含任何真实凭据**，全部通过环境变量注入：

| 环境变量 | 默认值 | 说明 |
|---------|--------|------|
| `DB_HOST` | localhost | MySQL 主机 |
| `DB_PORT` | 3306 | MySQL 端口 |
| `DB_NAME` | movie_dashboard | 数据库名 |
| `DB_USERNAME` | root | 数据库账号 |
| `DB_PASSWORD` | （空） | 数据库密码，**务必自行配置** |
| `SERVER_PORT` | **未启用** | 端口在 `application.yml` 中固定为字面量 `8081`（曾因环境变量 `SERVER__PORT` 被系统同名变量覆盖导致错乱，故弃用环境变量方式，与 nginx `proxy_pass` 严格对齐） |
| `DDL_AUTO` | update | JPA 建表策略，生产建议 `validate` |
| `SHOW_SQL` | false | 是否打印 SQL |
| `DB_POOL_MAX` | 10 | HikariCP 最大连接数 |
| `SPRING_PROFILES_ACTIVE` | local | 激活的配置文件（读取 gitignore 的 `application-local.yml`） |

优先级：**环境变量 > `application-local.yml`（不入库）> application.yml 默认值**。参见 `.env.example`。

## 七、二次开发与扩展指引

### 7.1 新增一个统计接口（以"演员作品榜"为例，4 步）

1. **DTO**：在 `dto/` 下新建 `ActorRankDTO.java`（手写 getter/setter + 全参构造，本项目未使用 Lombok）
2. **Repository/Service**：在 `StatsService` 新增私有 `computeActorRank(StatsContext ctx)` 方法（复用 `loadContext` 里的筛选结果），再包一个公开方法 `actorRank(q)` 供单独调用
3. **Controller**：在 `StatsController` 复制一个 `@GetMapping`，用 `buildQuery(...)` 组装 `MovieQueryDTO`；同时把结果塞进 `StatsOverviewDTO` 与 `overview()` 一起返回
4. **前端**：`charts/` 下新建模块（挂 `window.Charts.<key>`）→ 在 `chart-config.js` 加一行声明（容器 id、数据来源、转换函数、是否懒渲染）→ 在 `main.js` 的 `transformers` 里补一个 `transform*`

> 走 `chart-config.js` 声明式配置后，新增图表**不需要**再改 `reloadAll`、主题切换、resize 三处逻辑。

### 7.2 新增/修改筛选条件

`MovieQueryDTO` 加字段 → `MovieRepository` 的 JPQL 加条件 → `StatsService.filterMovies()` 加对应 filter → 前端 `filterParams()` 输出该参数。四处同步即可。

### 7.3 数据量变大后的优化点

| 现状 | 优化方向 |
|------|---------|
| 统计在 Java 内存分组 | 改为 `@Query` 原生 SQL `GROUP BY`，或引入物化视图 |
| 每次筛选全量查表 | 加 Redis 缓存热查询结果；或引入分页预聚合表 |
| 无索引优化习惯 | 确保 `release_year`、`rating`、`country`、`season_tag` 上都有索引（现已有） |

### 7.4 其他可扩展方向

- **用户登录 + 个人收藏**：加 `users` / `favorites` 表，Spring Security 或简单 Session 即可
- **推荐算法**：基于「类型 + 评分 + 导演」做协同过滤，作为新的 stats 接口
- **容器化部署**：补 `Dockerfile` + `docker-compose.yml`（MySQL + 后端 + Nginx 三件套）
- **导出功能**：后端加 CSV 导出接口，或前端用 Blob 直接导出当前筛选结果
- **换数据库**：改 `pom.xml` 驱动 + `application.yml` 里 `DB_*` 变量即可，JPA 层无需改动

## 八、编码规范与约定

| 约定 | 内容 |
|------|------|
| **不使用 Lombok** | 所有 Entity/DTO 手写 getter/setter 与构造器，避免 JDK 版本兼容问题 |
| **分层调用单向依赖** | Controller → Service → Repository，禁止反向或跨层调用 |
| **统一响应** | 所有接口返回 `Result<T>`；异常由 `GlobalExceptionHandler` 兜底 |
| **前端模块化** | 每个 JS 文件 IIFE 包裹，只通过约定的全局对象通信 |
| **分页基准** | 后端 0-based，前端 1-based，换算只发生在 `loadMovieList()` |
| **提交信息规范** | 采用 Conventional Commits：`feat:` / `fix:` / `docs:` / `refactor:` / `chore:` |
| **注释语言** | 类、方法、关键分支均写中文注释，便于课程验收与交接 |

## 九、已知边界

| 项 | 现状 | 说明 |
|----|------|------|
| 统计实现方式 | Java 内存分组 | 850 条数据下毫秒级返回；数据量达万级需改造（见 7.3） |
| 多类型筛选 | SQL 先过滤 + 内存 AND 补齐 | 保证语义正确，代价是一次全量捞取；多类型时 `totalElements` 按内存过滤结果重算 |
| 导演 TOP N 不随筛选联动 | `reloadAll()` 中 top-directors 只传 `n=20` | 当前为全量榜单；如需联动，把筛选参数一起传给该接口（后端已支持） |
| 无鉴权 | 接口完全开放 | 课程作业范围；如需鉴权参见 7.4 |
| 首次数据加载 | 从 classpath CSV 加载 | 生产环境建议改用 Flyway/Liquibase 管理迁移脚本 |
